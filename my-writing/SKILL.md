# ライティング

## 目的

ドキュメント作成を安定させる。

## 制約

### 推奨事項

- 目的が明確
- 端的な文章
- 決まりや方針は原則、否定文ではなく肯定文で書く
- セクションごとに見出しを設ける
- リンクはそのまま記述せず、`[名前](URL)`のように名前付きリンクとする
- 下記を参考に用途に応じて記法を選び、複数ある場合は先に書いた記法を優先する

  | 用途 | 記法 |
  | --- | --- |
  | 並列の項目 | リスト |
  | 手順 | 番号付きリスト、`flowchart`※ |
  | 作業項目、確認項目 | タスクリスト（`- [ ]`） |
  | 比較、一覧 | 表 |
  | 補足、注意 | アラート（`> [!NOTE]`） |
  | コード、コマンド | コードブロック |
  | 詳細の前の全体図 | `C4Context`※、`mindmap`※ |
  | ディレクトリ構成、ファイル構成、対象ファイル | `treeView-beta`※ |
  | 配置図 | `C4Deployment`※ |
  | コンポーネント図 | `C4Component`※ |
  | 関係性 | `mindmap`※ |
  | 概念の関係 | `classDiagram`※ |
  | データの関係 | `erDiagram`※ |
  | 複数の関係をまたぐフロー | `swimlane-beta`※ |
  | 単一のフロー | `flowchart`※、番号付きリスト |
  | 複数の登場者による時系列のやり取り | `sequenceDiagram`※ |
  | ユースケース | `flowchart`※ |
  | 状態遷移、アクティビティ図 | `stateDiagram-v2`※ |
  | 競合他社の比較 | `quadrantChart`※、表 |

  ※ Mermaid図

### 禁止事項

- 冗長な記述
- 日本語と英語の併記
- 5列以上の表

## ワークフロー

1. 推奨事項と禁止事項を確認して文章を編集する
2. 検証をして問題がなければ完了とする

## 検証

- 推奨事項は守られているか
- 禁止事項に該当しないか
